# 移植说明：界面与内部逻辑的接缝

这份文档回答三个问题：**移植了什么、UI 挂在哪里、想换成 PCL2 原生逻辑要动哪几处**。

## 1. 移植边界

| 层 | 位置 | 与 PCL2 的关系 |
| --- | --- | --- |
| 界面 | `src/MindCraftLauncher.App` | **新画**。保留 PCL2 的骨架：顶部标签条（启动/下载/联机/设置/更多）、右上主启动按钮、底部状态区 |
| 装配 | `Core/LauncherServices.cs` | **接缝层**。UI 唯一认识的入口，逻辑换实现只改这里 |
| 逻辑 | `src/MindCraftLauncher.Core` | 等价最小实现（下载、版本解析、启动参数、组网、认证），可整体替换 |

PCL2 本体是 VB.NET + WPF（约 10 万行级），"只改 UI 不改内部逻辑"要求拿到源码工程在手；本工程的做法是把 PCL 的逻辑边界**抽象成接口形状**，让你有两种落地路径（见 §4）。

## 2. UI → 逻辑的调用链

```
MainWindow (nav RadioButton)
  └─ MainViewModel ──持有──┬─ LaunchViewModel      → LauncherServices.Launcher / Accounts
                           ├─ DownloadViewModel    → LauncherServices.Versions / LabyMod / Sources
```

ViewModel 不 `new` 任何业务对象，全部经 `LauncherServices` 注入；页面切换由 `MainWindow.xaml.cs` 控制 Visibility，不涉及业务。

## 3. 关键接缝（想换 PCL 原生逻辑时动这几处）

| 接缝 | 当前实现 | 换成 PCL 的做法 |
| --- | --- | --- |
| 加载器安装 | `Clients/ModLoaderService.cs`（Fabric / Forge / OptiFine） |
| 整合包 / 模组 | `Mods/ModpackInstaller.cs`、`Mods/ModInstaller.cs` | 转调 PCL 的加载器安装模块，保持 `ListAsync` + `InstallAsync` 签名 |
| 版本列表 / 下载 | `Downloads/VersionInstaller.cs` | 转调 PCL 的下载模块（`TaskDesk` / 下载源选择），保持 `ListVersionsAsync` + `InstallAsync(id, progress, ct, clientOnly)` 两个签名 |

| 启动参数 | `Launch/GameLauncher.cs` | 转调 PCL 的 `MinecraftLaunch`，把 `LaunchRequest` 映射到它的入参，返回 `LaunchPlan` 供 UI 展示 |
| 功能开关 | `Config/FeatureFlags.cs` | 就是 PCL 里"本体下载是否可用"的那一处判断，集中成一个 bool + 一个确认时间戳 |
| 账号 | `Accounts/LauncherAccount.cs`、`AccountStore` | 换成 PCL 的账号体系（微软/外置/离线），注意 `Uuid` 统一用不带横杠的 32 位十六进制 |
| 外置登录 | `Yggdrasil/*` | PCL 原生已支持外置登录，替换后 UI 的 `RedstoneViewModel` 仍可复用（只依赖 `AuthenticateAsync` 与 `JavaAgentArgument.Build`） |
| 组网 | `EasyTier/*`、`Terracotta/*` | PCL2 官方无此模块（社区版 PCL CE 有陶瓦联机），这里的实现是独立的一份，可对照 PCL CE 的参数拼装做替换 |

## 4. 两条落地路径

**路径 A（推荐，工作量小）**：保持现在的 `Core`，把界面当作启动器的"外壳"使用。已经可跑通：装版本 → 启动 → 陶瓦组网直连 → 红石外置登录。

**路径 B（严格意义的"只改 UI"）**：拿到 PCL2 源码工程后——
1. 在 PCL 工程里新建 `Pages` 目录，把本仓库 `Themes/*.xaml` 与五个 `Views/*.xaml` 的视觉部分搬过去；
2. `Core/LauncherServices.cs` 的每个属性改成薄适配器，内部调用 PCL 已有的模块（下载、启动、账号、版本隔离）；
3. 陶瓦 / 红石两个页面新增到 PCL 的导航栏，逻辑用本仓库 `EasyTier/`、`Yggdrasil/` 两个目录（它们是 PCL 里没有的能力）。

PCL2 用的是 VB.NET，C# 工程引用它需要开启 `Microsoft.VisualBasic` 或直接混合编译；跨语言调用本身没问题，但 PCL 内部大量 `ModuleBase` 静态状态，适配时注意初始化顺序。

## 5. 联机接口约定

### 陶瓦联机

```csharp
TerracottaSession.StartHost(networkName, networkSecret, lanPort, publicPeer) → TerracottaState
TerracottaSession.Join(connectionCode, fallbackPublicPeer)                   → TerracottaState
TerracottaSession.RefreshAsync()                            → TerracottaState(虚拟IP, 可连地址, 节点表, 日志)
```

底层等价命令（由 `EasyTierArgs.Build` 生成，可复制到终端复现）：

```
easytier-core --network-name <name> --network-secret <secret> -d \
              -p tcp://public.easytier.cn:11010 -l udp://0.0.0.0:11010 --hostname <pc>
easytier-cli peer        # 状态表：ipv4 / hostname / cost / lat_ms / loss_rate / ...
```

连接码 = `MCL1.` + base64url(`{n,s,p,i,d,l}`)，字段即网络名/密钥/peers/虚拟IP/DHCP/游戏端口。

### 红石联机

Yggdrasil 规范四个端点（`YggdrasilClient` 已实现，`--live` 测试覆盖了解析部分）：

```
POST {apiRoot}/authenticate  {agent:{name:"Minecraft"},username,password,clientToken,requestUser}
POST {apiRoot}/refresh       {accessToken,clientToken,requestUser}
POST {apiRoot}/validate      {accessToken,clientToken}
POST {apiRoot}/invalidate    {accessToken,clientToken}
```

`apiRoot` 规范化为 `站点地址 + /api/yggdrasil`；注入 JVM 参数 `-javaagent:<jar>=<apiRoot>`。

## 6. 测试策略

- `tests/` 不引任何 NuGet 包（自带 60 行断言框架），保证离线还原不失败。
- 单元测试（48 项）只碰纯函数与临时目录，`dotnet run --project tests/...` 即可。
- 联网冒烟（12 项）`-- --live` 会真的拉 Mojang 清单、BMCLAPI 版本 json、LabyMod 频道清单与 profile、authlib-injector latest.json、Fabric loader 列表与 profile json、Fabric 镜像 meta、Forge maven-metadata 与 promotions_slim（并 HEAD 一次安装包直链）、OptiFine 镜像清单、Modrinth 搜索与真实 .mrpack 解析，还会下载历史版本 `1.0` 的客户端 jar 做 sha1 校验——目的是用**真实远端数据**验证解析器，而不是只测本地字符串。
